# Reproduce B14 on an isolated Linux host

B14 controls the AS154 candidate (`10.154.0.71`) at the IPv4 firewalls of AS150–AS153. AS154 is configured to dial AS153 (`10.153.0.71:3001`). The three producers retain their restrictions throughout the experiment.

## Install and prepare a fresh run

Use a dedicated Linux x86-64 VM with a local Docker engine. Follow [installation](install.md) for the pinned SEED Emulator revision, Python virtual environment, Docker, standalone `docker-compose`, Bash, curl, tar, and checksum tools. The controller also uses `flock` from util-linux and `awk`. Use the SEED virtual environment throughout. The installer verifies Cardano Node 11.1.3 and CLI 11.2.3.0. The host needs access to the release, image, and package sources for a first install and build.

Run in Bash from the repository root. Use a simple absolute run path without spaces or Compose metacharacters. The copy includes only source inputs.

```bash
umask 077
repo="$(pwd -P)"
name=B14-cardano-relay-admission
source_dir="$repo/experiments/$name"
run="$(mktemp -d /tmp/b14-run.XXXXXXXX)"
experiment="$run/experiments/$name"

mkdir -p "$run/scripts" "$experiment/scripts" "$experiment/config/"{"$profile",specs}
cp "$repo/scripts/"{setup-cardano.sh,prepare-genesis.py} "$run/scripts/"
cp "$source_dir/blockchain.py" "$experiment/"
cp "$source_dir/scripts/relay-admission.sh" "$experiment/scripts/"
cp "$source_dir/config/$profile/"{config.json,topology-node{1,2,3,4,5}.json} \
  "$experiment/config/$profile/"

Check the **generated** pool IDs, VRF hashes, delegations, and funded addresses against the new keys. A read-only check of existing output from the same CLI and identical Shelley template showed that generated entries replaced the template entries. Fresh B14 generation and block production remain to be verified. Stop if the checks fail and review the generated data before changing any parameters.

```bash
python3 - "$cli" "$config/shelley-genesis.json" <<'PY'
import json
from pathlib import Path
import subprocess
import sys
import tempfile

cli, genesis = sys.argv[1:]
shelley = json.loads(Path(genesis).read_text())
extra = shelley.get("extraConfig", {})
pools = extra.get("stakePools", {}).get("data") or shelley["staking"]["pools"]
delegations = extra.get("stakeCredentials", {}).get("data") or shelley["staking"]["stake"]
funds = extra.get("initialFunds", {}).get("data") or shelley["initialFunds"]
generated = Path("config/generated/testnet-conway-v2")

def command(*args):
    return subprocess.check_output([cli, *map(str, args)], text=True).strip()

def funded_address(payment, *args):
    address = command("address", "build", "--testnet-magic", 4242,
                      "--payment-verification-key-file", payment, *args)
    return json.loads(command("address", "info", "--address", address))["base16"]


pool_ids, stake_ids, addresses = set(), set(), set()
with tempfile.TemporaryDirectory(dir=".") as scratch:
    for n in (1, 2, 3):
        delegator = generated / "stake-delegators" / f"delegator{n}"
        stake = delegator / "staking.vkey"
        stake_ids.add(command("conway", "stake-address", "key-hash",
                              "--stake-verification-key-file", stake))
        addresses.add(funded_address(delegator / "payment.vkey",
                                     "--stake-verification-key-file", stake))
        addresses.add(funded_address(generated / "utxo-keys" / f"utxo{n}" / "utxo.vkey"))
        pool = generated / "pools-keys" / f"pool{n}"
        pool_id = command("conway", "stake-pool", "id", "--output-hex",
                          "--cold-verification-key-file", pool / "cold.vkey")
        pool_ids.add(pool_id)
        assert (pool / "opcert.cert").stat().st_size > 0
        for kind in ("vrf", "kes"):
            derived = Path(scratch) / f"pool{n}-{kind}.vkey"
            command("key", "verification-key", "--signing-key-file", pool / f"{kind}.skey",
                    "--verification-key-file", derived)
            assert json.loads(derived.read_text())["cborHex"] == json.loads(
                (pool / f"{kind}.vkey").read_text())["cborHex"]
        vrf = command("node", "key-hash-VRF", "--verification-key-file",
                      Path(scratch) / f"pool{n}-vrf.vkey")
        assert pools[pool_id]["vrf"] == vrf, f"Pool {n} VRF hash mismatch"

assert len(pool_ids) == 3 and set(pools) == pool_ids == set(delegations.values())
assert len(stake_ids) == 3 and set(delegations) == stake_ids
assert len(addresses) == 6 and set(funds) == addresses
assert all(amount > 0 for amount in funds.values())
assert sum(funds.values()) <= shelley["maxLovelaceSupply"]
print("Fresh producer key pairs and Shelley pool bindings verified")
PY
```

## Verify denial, admission, and revocation

Use paired, bounded captures on AS153 and AS154. Start each capture before the transition and leave it running through the corresponding probes. The commands use the container's `timeout` to interrupt tcpdump so it can flush its file. Use a new tag for a new attempt. Choose a longer window for slower runs. Keep the PCAPs and diagnostic output under the private runtime root.

```bash
start_capture() {
  local phase=$1 id endpoint log
  capture_pids=()
  for endpoint in relay candidate; do
    id=${!endpoint}
    log="$CARDANO_EXPERIMENT_RUNTIME/captures/$phase-$endpoint.stderr"
    test ! -e "$log" || return 1
    docker exec "$id" timeout -k 5 -s INT 120 tcpdump -Z root -i any -nn -s 0 -U \
      -w "/captures/$phase-$endpoint.pcap" 'host 10.154.0.71 and tcp port 3001' \
      2>"$log" &
    capture_pids+=("$!")
  done
  for endpoint in relay candidate; do
    log="$CARDANO_EXPERIMENT_RUNTIME/captures/$phase-$endpoint.stderr"
    timeout 10 bash -c 'until grep -q "listening on" "$1"; do sleep 0.2; done' _ "$log" ||
      { cat "$log" >&2; return 1; }
  done
}
finish_capture() {
  local pid rc failed=0
  for pid in "${capture_pids[@]}"; do
    rc=0
    wait "$pid" || rc=$?
    case $rc in 0|124) ;; *) printf 'Capture exited %s\n' "$rc" >&2; failed=1 ;; esac
  done
  return "$failed"
}
probe() { docker exec "$1" nc -z -w 3 "$2" 3001; }
denied_probe() {
  local rc=0
  probe "$1" "$2" || rc=$?
  if [ "$rc" -ne 1 ]; then
    printf 'Expected netcat denial at %s, got exit %s\n' "$2" "$rc" >&2
    return 1
  fi
}
controls() {
  local asn
  probe "$producer" 10.153.0.71 || return 1
  for asn in 150 151 152; do
    denied_probe "$candidate" "10.$asn.0.71" || return 1
  done
}
```

Run and review each block before continuing. The incumbent control must pass and the candidate DROP counters on the target should rise on denied attempts. An unreachable target or failed positive control leaves a denial result inconclusive.

### Existing TCP connections

Compare the same established four-tuple before and after revocation using `ss -tin` and the paired captures. Look for progress of the existing stream during admission, then stalled acknowledgments, retransmissions, or eventual closure during denial. Record the old flow separately from fresh probes. The original rule scope matches packets with destination port 3001. A flow can stall and remain `ESTABLISHED` until TCP or Cardano times out. The controller sends no resets and does not delete sockets or conntrack entries. If there was no established flow carrying traffic before the transition, record the held-flow check as inconclusive.

For an optional controlled check, run this block from the same shell as the phase checks, after the prior capture jobs have finished. It opens one Cardano CLI keep-alive connection from AS154 to AS153. A `network rtt:` line confirms that the CLI received a Cardano keep-alive response. The test waits for one response before revocation and then observes the same process for 15 seconds. Use a fresh capture tag on each attempt.

```bash
held_flow() {
  local tag=$1 log sockets ping_pid result=0 ping_result=0
  log="$CARDANO_EXPERIMENT_RUNTIME/captures/$tag-ping.log"
  sockets="$CARDANO_EXPERIMENT_RUNTIME/captures/$tag-sockets.txt"
  local -a ping=(timeout -k 5 90 docker exec -t "$candidate"
    timeout -k 5 80 cardano-cli ping --mode ping --color never
    --count 1000 --network-magic 4242 10.153.0.71:3001)
  local -a snapshot=(timeout 5 docker exec "$candidate"
    ss -tinp dst 10.153.0.71 dport = :3001)

  "${ping[@]}" >"$log" 2>&1 &
  ping_pid=$!
  if timeout 20 bash -c 'until grep -q "network rtt:" "$1"; do sleep 0.2; done' _ "$log" &&
    {
      printf 'Before revocation\n'
      date -u
      "${snapshot[@]}"
    } >"$sockets" &&
    grep -q '"cardano-cli"' "$sockets" &&
    kill -0 "$ping_pid"; then
    if timeout -k 5 20 bash ../scripts/relay-admission.sh revoke; then
      {
        printf 'Immediately after revocation\n'
        date -u
        "${snapshot[@]}"
      } >>"$sockets" || result=1
      local before after
      before=$(awk '/network rtt:/ {n++} END {print n+0}' "$log")
      sleep 15
      after=$(awk '/network rtt:/ {n++} END {print n+0}' "$log")
      printf 'Keep-alive responses during the observation window: %s\n' "$((after - before))"
      {
        printf 'After the observation window\n'
        date -u
        "${snapshot[@]}"
      } >>"$sockets" || result=1
    else
      printf 'Revocation could not be verified. Check status and restore the baseline.\n' >&2
      result=1
    fi
  else
    printf 'Held-flow check inconclusive. No verified live probe before revocation.\n' >&2
    result=1
  fi
  wait "$ping_pid" || ping_result=$?
  printf 'Keep-alive probe exited %s. See %s and %s.\n' "$ping_result" "$log" "$sockets"
  return "$result"
}

held_tag=04-held
held_result=0
start_capture "$held_tag" &&
  admission grant &&
  held_flow "$held_tag" || held_result=$?
finish_capture && test "$held_result" -eq 0
```

Match the `cardano-cli` socket's local port in the socket snapshots to the paired local PCAPs. No new keep-alive responses during the observation window indicates that application traffic stopped during that window, even if the socket still shows `ESTABLISHED`. If a response appears, use the capture and timestamps to distinguish in-flight data from a new exchange after revocation. A probe ending before revocation leaves the held-flow result inconclusive. If the block fails after granting access, run `admission restore` and `admission status` before retrying or cleaning up.

## Restore and clean up

Wait for capture jobs and close any foreground observers. After verifying the selected project and target services, restore the **startup B14 baseline**, with the candidate denied by all four incumbents and unrelated rules preserved.

```bash
printf 'Project %s, directory %s\n' "$COMPOSE_PROJECT_NAME" "$PWD"
docker-compose ps &&
  admission restore &&
  admission status &&
  docker-compose down
```

Review any controller error before continuing. Foreign rule ordering or unexpected B14-owned rules can prevent the controller from verifying the baseline. It reports the failure and leaves unrelated rules in place. If restore cannot be verified, use `status` and inspect the affected container, or tear down the verified disposable B14 project to remove its namespaces. Avoid concurrent manual firewall edits or container lifecycle actions during a transition. Fresh containers reapply startup denial. Bind-mounted databases, captures, and generated credentials stay in the private run directory.
