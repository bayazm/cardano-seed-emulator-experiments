# B15 fresh-chain reproduction

B15 runs AS180–AS182 as Cardano producers, AS183 as the incumbent relay and AS184 as the candidate. The ledger records membership through a Plutus V3 validator and a singleton registry NFT. AS183's IPv4 TCP/3001 firewall changes only when an operator invokes the enforcer. This procedure uses a fresh chain and empty node databases.

Installation, Aiken tests, genesis inspection, Compose rendering and parameter checks can run without a node. Genesis generation below makes real **lab** credentials and belongs in a private disposable directory. Docker startup, protocol and UTxO queries, transaction balancing and submission, firewall enforcement and packet checks are for an authorized live run.

The compiler imports KES, VRF and operational certificates from `pool1`–`pool3` into AS180–AS182 only. Generate a new set for each fresh chain. Keep credentials, generated genesis hashes and database state together for resuming an existing run.

The config selects Conway from epoch zero using the test hard-fork settings through Conway. Shelley initializes the protocol version to 9.0. The V3 blueprint and the genesis cost model are offline compatibility checks. Verify the effective era and protocol against the running ledger before balancing scripts. [Consensus initialization reference](https://ouroboros-consensus.cardano.intersectmbo.org/docs/references/miscellaneous/era_transition_governance/#initializing-the-chain-with-a-later-protocol-version)

## Verify baseline denial and prepare funding

Keep the AS183 default-deny rules installed by the compiler. Set up these private capture and probe helpers once. Run `observe` at each indicated stage.

```bash
observe() {
  local phase="$1" expected="$2" target container left right
  local candidate_rc=0 incumbent_rc=0 failed=0 capture_rc
  case "$expected" in allow|deny) ;; *) return 2 ;; esac
  for target in AS183 AS184; do
    if [ "$target" = AS183 ]; then container="$relay"; else container="$candidate"; fi
    timeout 22s docker exec "$container" timeout -s INT 18s \
      tcpdump -U -n -i any -s 96 -c 200 -w - \
      'tcp port 3001 and host 10.183.0.71 and host 10.184.0.71' \
      > "$run/evidence/b15-$phase-$target.pcap" \
      2> "$run/evidence/b15-$phase-$target-tcpdump.txt" &
    if [ "$target" = AS183 ]; then left=$!; else right=$!; fi
  done
  sleep 2
  timeout 8s docker exec "$candidate" sh -c '
    command -v nc >/dev/null || exit 127
    nc -z -v -w 3 -s 10.184.0.71 10.183.0.71 3001
    case $? in 0) exit 0 ;; 1) exit 10 ;; *) exit 2 ;; esac
  ' > "$run/evidence/b15-$phase-candidate-nc.txt" 2>&1 || candidate_rc=$?
  timeout 8s docker exec "$producer" nc -z -v -w 3 -s 10.180.0.71 10.183.0.71 3001 \
    > "$run/evidence/b15-$phase-incumbent-nc.txt" 2>&1 || incumbent_rc=$?
  printf 'Expected candidate policy: %s\nCandidate probe status: %s (0 connected, 10 failed to connect)\nIncumbent probe status: %s (0 connected)\n' \
    "$expected" "$candidate_rc" "$incumbent_rc" |
    tee "$run/evidence/b15-$phase-probe.txt" || failed=1
  docker exec "$relay" iptables-save -t filter > "$run/evidence/b15-$phase-AS183-rules.txt" || failed=1
  for container in "$left" "$right"; do
    capture_rc=0
    wait "$container" || capture_rc=$?
    [ "$capture_rc" -eq 0 ] || [ "$capture_rc" -eq 124 ] || failed=1
  done
  case "$expected:$candidate_rc" in
    allow:0|deny:10) ;;
    *) printf 'Candidate TCP check failed for %s\n' "$phase" >&2; failed=1 ;;
  esac
  if [ "$incumbent_rc" -ne 0 ]; then
    printf 'Incumbent TCP check failed for %s\n' "$phase" >&2
    failed=1
  fi
  return "$failed"
}
observe 00-baseline-denied deny

funding="$network/config/generated/testnet-conway-v2/utxo-keys/utxo1/utxo"
```

## Build, inspect and submit the exact body

The B15 build-only `--out-body` option keeps the balanced unsigned body and refuses to overwrite an existing path. The helper's original `--submit` path builds again. Use the following exact-body workflow so the transaction submitted is the one inspected. Run each submission only after review and live authorization.

```bash
body="$run/evidence"
view_body() (
  set -o pipefail
  "$cli" debug transaction view --tx-body-file "$body/$1.txbody" |
    tee "$body/$1-view.json"
)
record_predecessor() {
  registry verify --revision "$2" > "$body/$1-predecessor.json" &&
    jq -er '.reference' "$body/$1-predecessor.json"
}
view_transition() {
  local phase="$1" predecessor
  predecessor="$(jq -er '.reference' "$body/$phase-predecessor.json")" || return
  view_body "$phase" || return
  jq -e --arg predecessor "$predecessor" '.inputs | index($predecessor) != null' \
    "$body/$phase-view.json" >/dev/null || {
    printf 'Inspected body does not spend the recorded predecessor %s\n' "$predecessor" >&2
    return 1
  }
}
submit_body() {
  local phase="$1" expected signed_id
  shift
  expected="$("$cli" conway transaction txid --tx-body-file "$body/$phase.txbody" --output-text)" || return
  "$cli" conway transaction sign --tx-body-file "$body/$phase.txbody" \
    --signing-key-file "$funding.skey" "$@" --testnet-magic 5556 \
    --out-file "$body/$phase.signed" || return
  signed_id="$("$cli" conway transaction txid --tx-file "$body/$phase.signed" --output-text)" || return
  [ "$expected" = "$signed_id" ] || return 1
  docker exec -i "$producer" sh -ec '
    file=$(mktemp /tmp/b15-signed.XXXXXXXX)
    trap "rm -f -- \"$file\"" EXIT
    cat > "$file"
    cardano-cli conway transaction submit --tx-file "$file" \
      --testnet-magic 5556 --socket-path /cardano/node.socket
  ' < "$body/$phase.signed" || return
  printf '%s\n' "$expected" > "$body/$phase-txid.txt"
}
confirm_registry() {
  local phase="$1" revision="$2" expected reference predecessor="" asn container
  expected="$("$cli" conway transaction txid --tx-body-file "$body/$phase.txbody" --output-text)" || return
  registry verify --revision "$revision" > "$body/$phase-registry.json" || return
  reference="$(jq -er '.reference' "$body/$phase-registry.json")" || return
  [ "${reference%#*}" = "$expected" ] || {
    printf 'Confirmed registry reference does not match the inspected body\n' >&2
    return 1
  }
  if [ "$revision" -ne 0 ]; then
    predecessor="$(jq -er '.reference' "$body/$phase-predecessor.json")" || return
  fi
  for asn in 180 181 182 183; do
    container="$(node "$asn")" || return
    b15query "$container" utxo --tx-in "$reference" --output-json \
      > "$body/$phase-AS$asn-utxo.json" || return
    jq -e --arg ref "$reference" --arg address "$address" --arg policy "$policy" \
      --argjson revision "$revision" '
      .[$ref] | .address == $address
        and .value[$policy] == {"4231355f5245474953545259": 1}
        and .inlineDatum == {"constructor": 0, "fields": [
          {"bytes": "4153313834"}, {"bytes": "31302e3138342e302e3731"},
          {"constructor": ($revision % 2), "fields": []}, {"int": $revision}
        ]}' "$body/$phase-AS$asn-utxo.json" >/dev/null || {
      printf 'Unexpected successor output on AS%s\n' "$asn" >&2
      return 1
    }
    if [ -n "$predecessor" ]; then
      b15query "$container" utxo --tx-in "$predecessor" --output-json \
        > "$body/$phase-AS$asn-predecessor-utxo.json" || return
      jq -e 'type == "object" and length == 0' \
        "$body/$phase-AS$asn-predecessor-utxo.json" >/dev/null || {
        printf 'Predecessor %s is still unspent or its query is invalid on AS%s\n' "$predecessor" "$asn" >&2
        return 1
      }
    fi
  done
  printf 'Confirmed registry output from inspected body: %s\n' "$reference"
}
```

Use `view_body` for the collateral split and mint, and `view_transition` for authorization and revocation. Inspect the inputs, change and fee, output destination and value, mint field, datum and execution budgets, and required signers and collateral on script transactions. For transitions, record the unanimously observed predecessor before building. The view check requires it in the body's ordinary spending inputs. After confirmation, each incumbent must report the same expected successor and an empty UTxO query for the predecessor. The transaction ID commits to the body and ties the confirmed output to the inspected transaction. Wait for all incumbents to agree and for subsequent blocks before advancing. A successful submit response alone is only acceptance by the submitting node.

## Enforcement checks, recovery and cleanup

The controllers query the configured script address using each incumbent socket. They match the full policy ID and asset name, quantity one and expected inline datum. AS180–AS183 must agree on the UTxO reference and decoded state. Apply mode runs two checks against the required state and revision. AS183's running status, Compose project, service `hnode_183_host_0`, network namespace and IP are validated. The enforcers pin the inspected container ID and recheck it before each firewall change.

The shared `network/.runtime/b15-firewall.lock` serializes cooperating apply invocations in this checkout from the first registry query through firewall verification or recovery. It is released on exit. Keep the same project environment in every terminal. Coordinate manual firewall or container changes separately. The check is a ledger snapshot and can become stale before enforcement.

- **Uncertain submission or interruption.** Recover the body ID with `cardano-cli conway transaction txid --tx-body-file … --output-text`. Query the chosen output and original inputs across incumbents before attempting another build or submission. If the output matches, continue confirmation. If a registry input or seed was spent by a different transaction, reconcile the ledger state first. Check the collateral UTxO after failure. Keep prepared scripts and parameters if their mint may have confirmed. If preparation failed and no mint was built or accepted, preserve the incomplete deployment directory separately before preparing afresh with an unspent seed.
- **Incomplete admission or revocation.** Read the error and inspect both chain listings with `docker exec "$relay" iptables -w -S INPUT` and the corresponding `OUTPUT` command. Admission attempts to restore leading candidate DROPs on error. Revocation retains successful DROPs and reports a failed or unverified direction. If the ledger still authorizes the same operation, resolve the cause and repeat it. Verify both directions and repeat the packet probes. A lock conflict means another operation is in progress. Let it exit and check the actual ledger and rule state before retrying.
- **Clean shutdown.** Wait for bounded captures to end, retain private evidence only as needed, then use the same project and output file to stop the experiment.

