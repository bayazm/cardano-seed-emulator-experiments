# B16 fresh-chain reproduction

B16 adds authority-signed DID enrollment and Ed25519 proof of possession to supervised Cardano relay admission. AS180–AS182 produce blocks, AS183 is the incumbent and gateway, AS184 is the candidate, and AS185 is a separate negative-control host. The Plutus V3 registry authorizes a node/IP pair. The gateway joins that record to the signed off-chain enrollment and controls access to TCP/3001 at AS183.

Installation, unit tests, blueprint compilation, genesis inspection, and Compose rendering are offline. The genesis-generation command creates fresh **lab** keys and belongs in a private disposable run. For fixture-only validation, run the tests without that command. Chain startup, transaction balancing and submission, the namespace gateway, firewall changes, and packet observations require a dedicated live lab. No historical credentials, UTxOs, or evidence are needed.

The verifier compares the active and generated files for Byron, Shelley, Alonzo and Conway, recomputes their CLI hashes, and checks magic 5556, the common Byron/Shelley start and initial protocol 9.0. Alonzo and Conway supply era parameters; neither carries a separate start clock. It checks the Conway V3 cost model and Alonzo collateral settings, derives the addresses and pool identities from generated public keys, matches pool IDs and VRF keys to genesis, and derives public KES and VRF keys from the corresponding signing files for comparison. The compiler imports KES, VRF and operational certificates from `pool1`–`pool3` into AS180–AS182 only. Generate a new set for each fresh chain. Keep credentials, generated genesis hashes and database state together for resuming an existing run.

The config selects Conway from epoch zero using the test hard-fork settings through Conway. Shelley initializes the protocol version to 9.0. The V3 blueprint and the genesis cost model are offline compatibility checks. Verify the effective era and protocol against the running ledger before balancing scripts. [Consensus initialization reference](https://ouroboros-consensus.cardano.intersectmbo.org/docs/references/miscellaneous/era_transition_governance/#initializing-the-chain-with-a-later-protocol-version)

If generation is interrupted, preserve the failed directory for diagnosis and retry from a clean disposable source copy with a new start. The helper refuses to overwrite generated data. Mixing era files, producer credentials or databases from different generations invalidates the run.

## Verify network observations and baseline denial

Use the same shell variables throughout. These helpers write private evidence under the disposable run. A bounded capture uses both AS183 and AS184, with the port in each filename. The authentication and Cardano captures are separate.

```bash
start_capture() {
  local phase="$1" port="$2" name container
  capture_pids=()
  for name in AS183 AS184; do
    case "$name" in AS183) container="$relay" ;; AS184) container="$candidate" ;; esac
    timeout 22s docker exec "$container" timeout -s INT 18s       tcpdump -U -nn -i any -s 96 -c 200 -w -       "tcp port $port and host 10.183.0.71 and host 10.184.0.71"       > "$run/evidence/b16-$phase-$name-tcp$port.pcap"       2> "$run/evidence/b16-$phase-$name-tcp$port.txt" &
    capture_pids+=("$!")
  done
  sleep 2
}
finish_capture() {
  local phase="$1" port="$2" pid status name failed=0
  for pid in "${capture_pids[@]}"; do
    status=0
    wait "$pid" || status=$?
    case "$status" in 0|124) ;; *) failed=1 ;; esac
  done
  for name in AS183 AS184; do
    tcpdump -nn -r "$run/evidence/b16-$phase-$name-tcp$port.pcap"       > "$run/evidence/b16-$phase-$name-tcp$port-summary.txt" 2>&1 || failed=1
  done
  return "$failed"
}
probe() {
  local container="$1" ip="$2" expected="$3" status=0
  timeout 8s docker exec "$container" sh -c '
    command -v nc >/dev/null || exit 127
    nc -z -v -w 3 -s "$1" 10.183.0.71 3001
    case $? in 0) exit 0 ;; 1) exit 10 ;; *) exit 2 ;; esac
  ' sh "$ip" || status=$?
  case "$expected:$status" in allow:0|deny:10) return 0 ;; esac
  printf 'Unexpected probe from %s for %s: exit %s\n' "$ip" "$expected" "$status" >&2
  return 1
}
snapshot_rules() {
  docker exec "$relay" iptables-save -c -t filter
}
observe() {
  local phase="$1" expected="$2" failed=0
  start_capture "$phase" 3001
  probe "$candidate" 10.184.0.71 "$expected" > "$run/evidence/b16-$phase-AS184-nc.txt" 2>&1 || failed=1
  probe "$control" 10.185.0.71 deny > "$run/evidence/b16-$phase-AS185-nc.txt" 2>&1 || failed=1
  probe "$producer" 10.180.0.71 allow > "$run/evidence/b16-$phase-AS180-nc.txt" 2>&1 || failed=1
  snapshot_rules > "$run/evidence/b16-$phase-AS183-rules.txt" || failed=1
  finish_capture "$phase" 3001 || failed=1
  return "$failed"
}
observe 00-baseline-denied deny
```

At baseline both AS184 and AS185 probes must fail, AS180 must still connect, and the first rules of INPUT and OUTPUT must be AS185 DROP followed by AS184 DROP for TCP/3001. Compare the captures and rule counters to the probe results. A failed TCP connection alone can also reflect a routing or listener failure. Diagnose a capture error, Docker error, or outer timeout before advancing.

## Build, inspect and submit the exact body

The B16 build-only `--out-body` option keeps the balanced unsigned body and refuses to overwrite an existing path. The helper's original `--submit` path builds again. Use the following exact-body workflow so the transaction submitted is the one inspected. Run each submission only after review and live authorization.

```bash
body="$run/evidence"
view_body() (
  set -o pipefail
  local expected predecessor="${2:-}"
  expected="$("$cli" conway transaction txid --tx-body-file "$body/$1.txbody" --output-text)" || return
  "$cli" debug transaction view --tx-body-file "$body/$1.txbody" |
    tee "$body/$1-view.json" || return
  if [ -n "$predecessor" ]; then
    jq -e --arg predecessor "$predecessor" '.inputs | index($predecessor) != null' \
      "$body/$1-view.json" >/dev/null || {
      printf 'Inspected body does not spend the recorded predecessor %s\n' "$predecessor" >&2
      return 1
    }
  fi
  printf '%s\n' "$expected" > "$body/$1-inspected-txid.txt"
)
record_predecessor() {
  registry verify --revision "$2" > "$body/$1-predecessor.json" &&
    jq -er '.reference' "$body/$1-predecessor.json"
}
view_transition() {
  local phase="$1" predecessor
  predecessor="$(jq -er '.reference' "$body/$phase-predecessor.json")" || return
  view_body "$phase" "$predecessor"
}
submit_body() {
  local phase="$1" expected signed_id
  shift
  expected="$("$cli" conway transaction txid --tx-body-file "$body/$phase.txbody" --output-text)" || return
  [ "$expected" = "$(cat "$body/$phase-inspected-txid.txt")" ] || return 1
  "$cli" conway transaction sign --tx-body-file "$body/$phase.txbody" \
    --signing-key-file "$funding.skey" "$@" --testnet-magic 5556 \
    --out-file "$body/$phase.signed" || return
  signed_id="$("$cli" conway transaction txid --tx-file "$body/$phase.signed" --output-text)" || return
  [ "$expected" = "$signed_id" ] || return 1
  docker exec -i "$producer" sh -ec '
    file=$(mktemp /tmp/b16-signed.XXXXXXXX)
    trap "rm -f -- \"$file\"" EXIT
    cat > "$file"
    cardano-cli conway transaction submit --tx-file "$file" \
      --testnet-magic 5556 --socket-path /cardano/node.socket
  ' < "$body/$phase.signed" || return
  printf '%s\n' "$expected" > "$body/$phase-txid.txt"
}
confirm_registry() {
  local phase="$1" revision="$2" expected reference predecessor asn container
  expected="$("$cli" conway transaction txid --tx-body-file "$body/$phase.txbody" --output-text)" || return
  registry verify --revision "$revision" > "$body/$phase-registry.json" || return
  reference="$(jq -er '.reference' "$body/$phase-registry.json")" || return
  [ "${reference%#*}" = "$expected" ] || {
    printf 'Confirmed registry reference does not match the inspected body\n' >&2
    return 1
  }
  predecessor="$(jq -er '.reference' "$body/$phase-predecessor.json")" || return
  for asn in 180 181 182 183; do
    container="$(node "$asn")" || return
    b16query "$container" utxo --tx-in "$reference" --output-json \
      > "$body/$phase-AS$asn-utxo.json" || return
    jq -e --arg ref "$reference" --arg address "$address" --arg policy "$policy" \
      --argjson revision "$revision" '
      .[$ref] | .address == $address
        and .value[$policy] == {"4231355f5245474953545259": 1}
        and .inlineDatum == {"constructor": 0, "fields": [
          {"bytes": "4153313834"}, {"bytes": "31302e3138342e302e3731"},
          {"constructor": ($revision % 2), "fields": []}, {"int": $revision}
        ]}' "$body/$phase-AS$asn-utxo.json" >/dev/null || {
      printf 'Unexpected successor output on AS%s\n' "$asn" >&2
      return 1
    }
    b16query "$container" utxo --tx-in "$predecessor" --output-json \
      > "$body/$phase-AS$asn-predecessor-utxo.json" || return
    jq -e 'type == "object" and length == 0' \
      "$body/$phase-AS$asn-predecessor-utxo.json" >/dev/null || {
      printf 'Predecessor %s is still unspent or its query is invalid on AS%s\n' "$predecessor" "$asn" >&2
      return 1
    }
  done
  printf 'Confirmed registry output from inspected body: %s\n' "$reference"
}
```

Use `view_body` for the collateral split and `view_transition` for mint, authorization and revocation. The mint predecessor is the wallet seed UTxO. Later predecessors are registry UTxOs. Inspect the inputs, change and fee, output destination and value, mint field, datum and execution budgets, and required signers and collateral on script transactions. For transitions, record the unanimously observed predecessor before building. The view check requires it in the body's ordinary spending inputs. After confirmation, each incumbent must report the same expected successor and an empty UTxO query for the predecessor. The transaction ID commits to the body and ties the confirmed output to the inspected transaction. Wait for all incumbents to agree and for subsequent blocks before advancing. A successful submit response alone is only acceptance by the submitting node.

Use the following helper to launch one controlled gateway, wait for its ready signal, and run the candidate. It saves the gateway log and candidate JSON separately. The candidate exits unsuccessfully for a denied decision after printing its result. Check that result to distinguish policy denial from transport failure.

```bash
authenticate() {
  local phase="$1" expected="$2" gateway_pid attempt ready=0 candidate_status=0 gateway_status=0 failed=0
  local gateway_log="$run/evidence/b16-$phase-gateway.log"
  local response="$run/evidence/b16-$phase-candidate.json"
  start_capture "$phase" 4040
  sidecar_live gateway > "$gateway_log" 2>&1 &
  gateway_pid=$!
  for attempt in {1..20}; do
    if grep -q '^B16_REMOTE_ADMISSION_GATEWAY_READY$' "$gateway_log"; then ready=1; break; fi
    if ! kill -0 "$gateway_pid" 2>/dev/null; then break; fi
    sleep 0.25
  done
  if [ "$ready" -eq 1 ]; then
    sidecar_live candidate > "$response" 2> "$run/evidence/b16-$phase-candidate.stderr" ||
      candidate_status=$?
  else
    failed=1
    # The gateway has a bounded accept timeout. Wait for it before retrying.
  fi
  wait "$gateway_pid" || gateway_status=$?
  finish_capture "$phase" 4040 || failed=1
  [ "$gateway_status" -eq 0 ] || failed=1
  case "$expected:$candidate_status" in
    ALLOW:0) jq -e '.authenticated and .decision == "ALLOW" and .network_admission == "GRANTED"' "$response" || failed=1 ;;
    DENY:1) jq -e '.authenticated and .decision == "DENY" and .network_admission == "NOT_GRANTED"
                   and .authorization_reason == "CARDANO_AUTHORIZATION_REVOKED"' "$response" || failed=1 ;;
    *) failed=1 ;;
  esac
  return "$failed"
}
authenticate 02-valid-did-unauthorized DENY
observe 02-valid-did-unauthorized deny
```

At revision 0 the genuine candidate proves key possession, but the gateway denies firewall admission. The TCP/4040 capture shows the challenge session. The TCP/3001 capture and rule snapshot show the separate deny policy.

## Lock, failure recovery and cleanup

The gateway, N17 apply path, and emergency rollback use the same host lock at `/run/b16-firewall.lock`. Privileged execution creates the regular file as root with mode `0600`. The network namespace launcher shares the host mount namespace, so its staged gateway and host-side enforcers use the same file. The nonblocking lock covers target validation, rule reads and edits, verification, and any rollback. Authentication, ledger queries, and capture or probe activity run outside it. Docker and iptables waits inside the lock are bounded. The kernel releases the lock when the file descriptor closes, including process exit. The lock file remains until the host clears `/run`. Do not delete or replace it during a run. An overlapping cooperating operation fails immediately. Reconfirm the intended ledger state before retrying. Manual firewall edits and container lifecycle changes require separate coordination.

Before writes, the controller checks the running container, exact AS183 name, Compose project and service labels, expected network attachment and mode, and both inspected and namespace IPv4 address. The controller pins the full container ID and revalidates it before each write. If the target changes, policy operations fail. If a partial operation or rollback fails, inspect both chain orders and traffic before treating AS184 as blocked. A later ledger revision can supersede a prior observation before enforcement.
